# Agent S3 接入演示托盘：实施方案（v2 定稿，11/19 晚）

决定来源：`docs/通用桌面操作-方案草案.md` 开头的决定表。v1 经 Codex 只读审核，v2 已吸收审核意见（见文末"相对 v1 的改动"）。

## 目标和完成条件

11/24 演示加分项：在 D16 演示托盘里点"电脑助手"，输入一句话，Agent S3 现场操作电脑，结束后用左右分栏回看每一步。

完成条件（都要实测，结果如实记录，不挑轮次）：

1. 两个演示任务各**连续 3 次**成功、无人干预、从回车到结束 ≤ 3 分钟（计时包含等微信监听停下）。成功由人/脚本核对实际界面，不以模型说 DONE 为准：
   - 任务 B：`打开 Chrome，进入 B 站，搜索"深圳湾 航拍"，点开一个视频`。核对：Chrome 当前是 B 站视频播放页，且是从"深圳湾 航拍"搜索进入的。
   - 任务 D：`打开 Windows 设置，搜索"深色模式"，把系统切换成深色模式`。核对：注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` 的 `AppsUseLightTheme=0`。每轮后脚本改回 1。
2. 开始 S3 时微信自动回复若在跑，等监听进程**真正退出**后才启动 S3；S3 无论怎么结束，都只恢复一次监听，参数和原来一样。
3. 托盘停止 S3 后 2 秒内，worker 及其子进程全部退出（S3 用开始菜单打开的应用不算，它们不是子进程）。
4. D16 现有离线测试全部通过。

不做：不加安全拦截，不改 Agent-S 源码，不合并 ufo2 分支，不做 UFO² 切换，不做运行中的置顶窗口。

- 屏幕 1920×1080，缩放 100%。
- D16 托盘：`D:\Newitem\edge-agent-d16`，分支 `codex/d16-reply-eval`。监听由 `agent/desktop_runner.py` 的 `Runner` 管理（停止文件 + 最长 90 秒后强杀），`Runner` 没保存启动参数。

## 做法（按阶段，前一阶段不过不进下一阶段）

### 0. 分支和工作树

从 `codex/d16-reply-eval` 当前头新建分支 `codex/s3-demo`，工作树 `D:\Newitem\edge-agent-s3`。把 D16 工作树里被 git 忽略、托盘启动需要的本机文件（`agent/test_contacts.local.json`、`agent/tone.local.json` 等，以 D16 实际导入为准）复制过去。原托盘和新托盘不同时开（共用 `desktop.lock`）。不碰 D16、ufo2 两个工作树的未提交内容。

### 阶段 A：原版 CLI 先跑通（不写托盘代码）

- 写一个最小启动脚本（放新工作树 `agent/s3/run_cli.py`，用项目 Python 运行）：用 D16 的 `agent.tools.secrets.get_key(target)` 读上面那个凭据，校验 profiles.json 里对应条目的 model 和地址，只放进子进程环境变量；然后用 `subprocess` 以 Agent-S 的 `.venv\Scripts\agent_s.exe` 和上面的参数加 `--task` 运行原版 CLI，工作目录 `D:\Newitem\Agent-S`。key 不打印、不写文件、不进命令行。
- 跑之前准备测试桌面：微信窗口用 Win32 `ShowWindow(SW_MINIMIZE)` 最小化（不按 Esc，不点按钮），桌面上不留私人内容窗口。
- B、D 各跑一次。记录：是否成功（按上面的核对法）、步数、用时、失败出在规划/定位/执行哪一环。
- **通过线：B、D 各至少成功 1 次。** 不过就停下汇报，不进入阶段 B。

### 阶段 B：worker、互斥、停止

**worker `agent/s3/worker.py`**（用 Agent-S 的 `.venv` 运行，不 import D16 的包）：

- 和 CLI 行为一致：构造 `OSWorldACI(env=None, platform="windows", 两组引擎参数, width/height=原屏尺寸)` 和 `AgentS3(..., max_trajectory_length=8, enable_reflection=True)`；截图按最长边 2400 缩放；每个任务 `reset()`；15 步；`DONE`/`FAIL` 精确判断、`next`/`wait` 子串判断，和 `cli_app.run_agent` 一致；`env=None` 保持原默认（不开代码代理）。
- 不注册 CLI 的交互式 Ctrl+C，日志自己初始化到 `%LOCALAPPDATA%\edge-agent\logs\s3-*.log`，不在 Agent-S 目录建 logs。
- 启动第一件事：创建 Windows Job Object（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），把自己放进去，之后的子进程都跟着进 job。
- key 只从环境变量 `DEEPSEEK_API_KEY` 读（由托盘读凭据后注入）。
- 标准输出一行一个 JSON（`ensure_ascii=True`，`flush`）：
  - `{"event":"start","task":...}`
  - `{"event":"thinking","n":k}`（`predict` 前）
  - `{"event":"executing","n":k,"plan":...,"code":...,"click":[x,y]|null,"shot":路径}`（`exec` 前）
  - `{"event":"executed","n":k,"seconds":...}`（`exec` 返回后）
  - `{"event":"done","result":"DONE|FAIL|STEP_LIMIT|ERROR","detail":...,"seconds":...}`
- `plan` 取 `info["plan"]`（完整模型输出），截前 300 字。动作短描述由托盘端从 `info["plan_code"]` 的 `agent.<函数名>` 推出（点击、输入、快捷键、滚动、拖拽、打开应用、等待、完成）。
- `click`：只取 `exec_code` 里字面量 `pyautogui.click(x, y` 的第一个坐标（`type` 带目标时也会先生成这一句）；没有就 null。
- 截图：每步发给模型的那张原尺寸截图存 `%LOCALAPPDATA%\edge-agent\s3-runs\<时间戳>\step-<k>.png`。演示结束后统一删除。

**托盘侧 `agent/s3/runner.py`**（照 `desktop_runner.Runner` 的写法）：

- `QProcess` 以绝对路径启动 `D:\Newitem\Agent-S\.venv\Scripts\python.exe -u -m agent.s3.worker --task ...`，工作目录为新工作树根（让 `agent.s3.worker` 可导入，worker 内自行把 `D:\Newitem\Agent-S` 加进 `sys.path`）；环境变量加 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`、`DEEPSEEK_API_KEY`（托盘用 `secrets.get_key` 读）。stdout 按字节攒满一行再解码；stderr 单独收进日志。路径、模型参数放 `agent/config.json` 新增 `"s3"` 段。
- 停止：`taskkill /T /F /PID <QProcess pid>`，然后异步确认进程已退出（Job Object 兜底子进程）。
- 结束收尾只有一个入口（正常结束、失败、崩溃、启动失败、手动停止都走它），保证只恢复一次监听。

**和微信监听互斥**（改 `desktop_runner.Runner` 和 `desktop.py`，改动尽量小）：

- `Runner.start(extra)` 记住 `self.last_extra = list(extra)`。
- 点"开始"：若监听在跑，先锁住左栏"开始/停止自动回复"按钮和托盘菜单对应项，调 `runner.stop()`，**等 `finished` 信号（进程真正退出）后**再启动 S3；等待期间状态行显示"正在停下微信自动回复…"。等待期间用户点停止或退出托盘，就取消这次待启动。
- S3 收尾后：如果之前停过监听，用 `last_extra` 调 `runner.start()` 一次，并解锁按钮。
- 监听被 90 秒强杀的情况，沿用 Runner 现有提示（提醒看输入框草稿），不另做处理。
- 托盘退出时，若 S3 在跑先停 S3，再走原来的退出流程。

**阶段 B 通过线**：从托盘（窗口可先用最简列表）跑 B、D 各 1 次成功；监听开着时启动一次，确认先停后起、结束后恢复到"监听中"；停止按钮测一次，2 秒内 worker 退出。

### 阶段 C：分栏界面

- `Inbox` 左栏"模型设置"上方加"电脑助手"按钮，托盘右键菜单加"电脑助手"和"停止电脑助手"两项。
- S3 窗口（独立 `QWidget`，参考 UI-TARS Desktop）：左栏约 40%，顶部输入框、开始/停止按钮、状态行，下面是步骤卡（第几步、计划摘要两行、动作短描述、用时）；右栏约 60%，显示选中步骤的截图，按实际绘制区域换算后在 `click` 处画红圈（半径约 18px，2px 红边，中心红点）。
- **运行中隐藏**：点开始后，S3 窗口和托盘主窗口都隐藏，托盘图标提示"电脑助手运行中"，停止入口在托盘右键菜单。结束后自动弹出 S3 窗口，选中最后一步，便于讲解每一步点了哪里。
- 状态行：运行中"第 k 步 · 正在思考/正在执行"和总用时（托盘提示里也显示）；结束显示结果和总用时。

### 阶段 D：连续验收和录屏

- 从托盘把 B、D 各连续跑 3 次，按完成条件核对，每轮一行记录（任务、结果、步数、用时、失败原因）。
- 跑 D16 现有离线测试。
- 结果写新工作树 `docs/evidence/S3/README.md`。不放微信截图，S3 截图只在本机数据目录。
- 录屏由用户在 11/20 晚进行，不在本次范围。

## 11/20 补充：演示前的桌面准备（用户定）

阶段 A 第一轮实测（任务 B）失败：15 步 380 秒；点缩略图落到 Codex 窗口后焦点丢失，S3 在切回 Chrome 的过程中点了微信关闭按钮并按了 Esc，微信主窗口被收进托盘。用户定：**每次跑 S3 前由用户手动把微信收进托盘，关掉 Codex、QQ 邮箱等无关窗口，桌面只留 Chrome；演完再从托盘恢复微信。** 不给 S3 加限制。之后的实测都在这个前提下进行。

## 相对 v1 的改动（来自 Codex 审核）

- 先用原版 CLI 跑通两条任务，再写托盘代码。
- 互斥改为等监听进程真正退出再启动 S3，保存启动参数，锁按钮，单一收尾入口只恢复一次。
- 停止改为 taskkill + Job Object + 确认退出；验收口径写明开始菜单打开的应用不算。
- 去掉运行中置顶窄条和 WDA 截图排除（置顶窗仍可能吃点击，且截图排除在本机未实测），改为运行中隐藏、结束后回看。
- worker 按 CLI 的构造参数和分支逻辑逐项对齐；不注册交互式 Ctrl+C；补上定位端 key `EMPTY`；事件细分为思考/执行/已执行。
- 红圈只标字面量 `pyautogui.click`；计划取 `info["plan"]`，动作取 `plan_code`。
- key 由托盘侧用 D16 的 `secrets.get_key` 读（worker 不导入 D16 包），用明确的凭据名并校验配置。
- 补上新工作树需要复制的忽略文件、测试桌面准备（微信最小化）、外部核对成功、截图保留期限。
