# D8 验收记录（11/4）

## 微信：10 轮（通过线 ≥8 且 0 误发）

命令：`python -m agent.core.graph <白名单好友> "测试 N"`，N = 4…13，窗口 960×800，开始时停在目标会话。

| 项 | 结果 |
|---|---|
| 程序判定通过 | 8/10（第 3、6 轮判失败） |
| 实际发出（人工看聊天记录） | 10/10，每条只发一次，内容都对 |
| 误发（发错人、发错字、重复发） | 0 |
| 结论 | **通过** |

两轮失败都是**核对误判**：消息确实发出去了，`verify_sent` 没数到新气泡。下一步：回车后多等一会儿再截图，或重试一次再判。

调通过程中修的问题：
- 聊天区下沿 `CHAT_BOTTOM` 710 → 645（按 960×800 重量；原值把输入框算进聊天区）
- `count_before` 只在按回车前数
- 规矩加两条：没按过回车不许 done；不许点「发送」按钮（焦点会跑到按钮上）
- 提示词：输入框有字不算完成

已知局限：坐标线跟窗口大小绑定；这 10 轮都从目标会话开始，没测"从别的会话切过去"。

## 邮件：10 封回复（通过线 ≥9 且 0 错收件人）

命令：`python -m agent.core.mail_nodes N`，N = 1…10（11/6，分两次跑：4…10，补 1…3）。收件箱先清空，再用 `agent.demos.seed_test_mails 10` 重发 10 封测试邮件。日志 `mail_run.log`、`mail_run_1-3.log`。

| 项 | 结果 |
|---|---|
| 程序判定通过 | 10/10 |
| 每封都真的打了字（日志里有 `type`，正文检查放行） | 10/10 |
| 错收件人 | 0（收件人只有测试号自己） |
| 结论 | **通过** |

前两批没过，记下来：
- 第 1 批 8/10：模型把"正文"点到引用区里。修法：target 带"正文"一律定位到正文框。
- 第 2 批表面 8/10，实际约 2/10：模型打开旧的"回复："邮件，规矩在引用区里找到上次的"测试回复 k"，就放行了空正文。修法：`body_text` 只看自己写的部分，提示词里不许点"回复："开头的邮件。
- 第 3 批 3/10：核对在「已发送」刷新前就数了，上一封晚到，算到下一封头上；模型跳步骤（没回复就点正文、点发送）；危险词查的是整句 target，"「删除」右侧的「回复」"被拦；旧回复太多，原邮件被挤出可见区。修法：核对每秒数一次，最多 10 秒；提示词写死 5 步顺序，被拦就按原因做；危险词只查最后一段引号里的字；清空收件箱再测。

已知局限：
- 「已发送」只读得到可见的大约 15 行；同一封偶尔会被数成 2 封（第 5 封），所以只看比发之前多没多。
- 粘贴时 ctrl+a 会把引用的原邮件一起换掉。
- 点正文后画面没变，也会记一次失败（第 6 封）。
- 前提是原邮件在收件箱可见区内；没有测要滚动才找得到的情况。

## 验收后发现的问题（11/5）

- **输入框里有用户草稿时，模型第一步直接按回车，把草稿发了出去。** 核对没认（判"没多出这条消息"），但草稿已经发出。
  修法：规矩 4.2，回车只许紧跟在“这次 type 过、且核对过输入框里有要发的那句话”之后。
