# 实验计划：探索一次，以后按固定步骤做（11/11，交给 Codex）

## 一句话目标

验证这条路能不能成立：开放任务第一次由模型边看边探索，跑通后把步骤存成一份"做法"；以后同类任务换个参数，由程序按做法执行，不再每一步都问模型。

**这次只验证后半段（固定步骤）。** 前半段的探索直接用现成的 Agent S 记录 `experiments/explore-then-fix/agent_s_trace.txt`。后半段最没把握，所以先测；它不通过，前半段就没必要做了。

限时：**半天**。到时间没做完，就停下来，交回当时的结果。

## 背景（为什么做）

- Agent S 探索"把某个文件夹里的文件发给文件传输助手"，11 步、3 分 45 秒还没做完，每步 14–32 秒，因为一步要调 3–4 次模型、每次写一大段。
- 我们自己的 agent 发一条消息一步 3–6 秒，但只会做写死的流程，不通用。
- 想要的效果：第一次慢可以接受，第二次起应该接近我们现在的速度。

## 要回答的三个问题（就是通过条件）

| # | 问题 | 怎么判断 |
|---|---|---|
| 1 | 探索记录能不能**自动**转成一份能重放的做法 | Qwen 读 trace，输出做法（JSON）。人工不改，或最多改 1 处，算过 |
| 2 | 做法里的步骤能不能**不靠坐标** | 每一步只用快捷键、粘贴、按文字找位置（OCR）、窗口句柄激活这几种方式表达。出现写死的屏幕坐标就不算过 |
| 3 | 重放**快且安全** | 换 2 个不同的文件夹参数，共重放 5 次：成功 ≥ 4 次，**误发 0 次**，每次 ≤ 20 秒（从开始到核对完） |

## 要做的东西

都放在 `experiments/explore-then-fix/` 下，**不要改 `agent/` 下的已有代码**，只 import 现有函数。

### 1. `make_recipe.py`：trace → 做法

- 输入 `agent_s_trace.txt`；输出 `recipe.json`。
- 调 Spark 上的 Qwen（`agent.tools.chat`，地址从 `agent/config.json` 读，关掉思考模式），一次调用完成。
- 做法的格式由你设计，至少包含：
  - **参数**：例如 `folder`（文件夹路径）、`to`（会话名）。原 trace 里的具体值必须换成 `{folder}`、`{to}` 这种空位。
  - **步骤**：每一步写动作和核对条件。动作只允许下面"可用动作"里那几种。
  - **核对条件**：每一步做完怎么确认成功，比如"OCR 看到地址栏里有 {folder} 的最后一段""会话标题是 {to}"。
- 让模型顺手去掉 trace 里的弯路：第 6–8 步切换应用失败、第 9–11 步点错到"收藏"，都不应该进做法。
- 打印模型原样输出和解析后的结果；记一下这次调用花了几秒、输出了多少 token。

### 2. `replay.py`：按做法执行

- 用法：`python experiments/explore-then-fix/replay.py --folder "<路径>" --to 文件传输助手`
- 按步骤执行，**不调 Qwen**。如果某一步实在需要定位，只允许用 OCR 按文字找；找不到就停。
- 每步做完按核对条件检查，不过就**停下并打印原因**，不重试，不退回探索。
- 每步打印：步骤名、耗时、核对结果。最后打印总耗时和结果（成功 / 停在第几步 / 原因）。

**可用动作**（只用这些，都已经在工具层里）：
- 按键 `agent.tools.press`（它已经拒绝 Esc 和 Alt+F4）
- 粘贴文字 `agent.tools.paste_text`（注意 `mode` 参数）
- 按 OCR 文字点击：`agent.tools.ocr` / `find_text` 找到文字 → `shot.to_screen` → `agent.tools.click`
- 窗口：`agent.tools.find_windows`、`activate`、`check_responsive`、`capture_window`
- 微信窗口和会话：`agent.core.graph.find_wechat`、`agent.core.trigger.prepare`、`agent.core.trigger.open_chat`
- 把文件放进剪贴板（"复制文件"）：工具层没有现成函数，你在实验目录里写一个（Windows 的 CF_HDROP 格式），不要用 shell 命令代替

### 3. 发送那一步（最要紧）

现有的 `graph.send_permit` 是为文字消息写的，靠剪贴板读回输入框，文件消息读不回来。这次单独写一个文件版的发送许可，**按回车前最后一刻**必须同时满足：

1. 重新截图，会话标题正好是 `{to}`（参考 `agent.core.check.title_matches`）。
2. 输入框里出现了这个文件的卡片，OCR 能看到文件名；输入框里没有别的文字草稿。
3. 文件夹里的文件就是发送前列出来的那些，数量和名字都对得上。

不满足任何一条，就不按回车，打印原因，停下。

**按回车最多 1 次。** 按完以后，核对聊天区右侧（我们自己发的那一边）新增了带这个文件名的消息；核对不过就判"不确定"，**不重发**。

## 安全硬规则（违反任何一条，立即停）

- 只发给 **文件传输助手**。`--to` 不是它就直接退出，一步都不做。
- 要发的文件夹只能用实验专用的，内容由你自己生成，比如 `D:\Newitem\_explore_test\A`、`...\B`，每个文件夹里放 1 个小 txt，内容就写"探索实验文件 A1"这种。不要用桌面上 SOP 文件夹里的真实文件。
- 不按 Esc；不点关闭、最小化；不点"收藏"、表情等工具栏图标；不点任何"发送"按钮，只按回车。
- 操作微信窗口前先 `check_responsive`。
- **任何一处被拦下或核对不过，就停。不要补发，不要自己换办法再试。** 停下后把现场原样报告回来。
- 微信截图不存进项目；打印里不出现聊天内容，只打印文件名、标题是否匹配、耗时。
- 跑真机时，会话前台不要有别人在用电脑；跑之前先确认一次。

## 分两段做

1. **离线段**（先做，不碰微信）：写完 `make_recipe.py` 并生成 `recipe.json`；写完 `replay.py`。参数校验、步骤调度、发送许可这三块用假的截图或 OCR 数据做单测（写在同目录的 `test_replay.py`），全过再进下一段。
2. **真机段**：在文件传输助手上跑。文件夹 A 跑 3 次，文件夹 B 跑 2 次。每次记总耗时、步数、结果。

1. 三个问题各自过没过，附数字：做法人工改了几处；有没有坐标；5 次重放的成功次数、误发次数、每次耗时。

3. 哪一步最容易出问题，为什么。
