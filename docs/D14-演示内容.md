# D14 定下的演示内容（11/11）

D14 复盘只定三件事：演示什么、指标线、方案取舍。D11–D13 的稳健性边角用户感知不到，不进复盘，只留在交接笔记里备查。

## 演示交付什么

| # | 交付 | 状态 | 对应日程 |
|---|---|---|---|
| 1 | **正确、无遗漏地回复别人**：微信和 QQ 邮箱来了消息，自动打开会话、回复，回到对的人 | 主线，必须完成。收发流程已有，回复内容还是写死的测试句 | D15–D16 回复生成 |
| 2 | **按知识库回复** | **先放一放**，只留检索接口，默认关掉 | 以后接 WeKnora |
| 3 | **一句话执行任务**：说一句话，它自己规划着做完 | 加分项，不是必须。可以用在线 API，可以借鉴别人的 agent | D20–D21 |

## Claude 补充、一起演示的点

- **快**：从来消息到回复发出，控制在一个看得见的时间内。提速靠固定流程交给程序，模型只写回复（原 D18 技能固化）。
- **像本人**：回复的语气照用户自己写的范例来，盲测分辨不出是不是本人写的。
- **不编造**：资料和对话里没有的，不硬答，转给人。
- **无遗漏可数**：用固定的测试脚本发消息，数漏回和回错人的条数。
- **看得见它干了什么**：一个小面板列出回了谁、回了什么、哪些转给了人。
- **讲清数据边界**：模型都跑在公司自己的 Spark 上，聊天内容不出公司。
- **备份视频**：现场出问题时放录像。

## 指标线

具体数值由 TIBO 定。

| 指标 | 怎么量 | 线 |
|---|---|---|
| 回错人、误发 | 固定测试脚本，多会话轮流发 | 必须为 0 |
| 漏回 | 同上，数没回的条数 | 必须为 0 |
| 回复速度 | 从消息出现到回复发出 | 待定（Claude 建议 ≤15 秒，计划书原写 ≤30 秒） |
| 语气像本人 | 盲测：把本人写的和 agent 写的混在一起让人猜 | 待定（Claude 建议 10 条里 ≥7 条猜不出） |
| 不编造 | 准备资料外的问题，看是否转人工 | 编造为 0 |

## 方案取舍

- **知识库**：先不接，回复生成里留一个检索函数和开关。开关关着时只按对话内容和语气范例来写。WeKnora 的现状和登录方式见 Agent Mail 项目 `D:/Newitem/weknora` 的 #216、#217、#218。
- **提速**：不换模型，不缩图（实测缩图不快），把固定流程交给程序，减少模型的调用次数和输出字数。
- **借鉴别人的 agent**：试了 UI-TARS-desktop、Agent S，读了 Agent S4 的文档。可以借鉴的是：按一句话找图标、拆任务、优先用快捷键、每步复盘、从跑过的轨迹里提炼固定步骤。不借鉴的是：让模型执行任意代码，以及整套进化筛选（要虚拟机集群和能自动判分的任务集）。
- **"先探索、后固定"**：给一句话任务用。计划在 `docs/实验-探索后固定.md`，还没验证（Codex 的沙箱连不上 Spark）。验证通过才进 D20–D21。
