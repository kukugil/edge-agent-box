## 已知局限（按设计或留到以后）

- **合并：** agent 正在给某个会话打字时，这个会话又来的消息排在回复上面，算被这次回复合并，不再单独回。按 D9"一个会话回一次"可以接受。D15 回复改成按内容写后就是真漏，要在按回车前比一次聊天区，见交接笔记。
- **切换会话的缝：** 从会话 A 切去回 B 时，"截图到点下去"那约 0.6 秒里 A 来的消息会漏。根治要每个好友一个独立聊天窗口（D11）。
- **有人同时用电脑时会多回：** 测试中两次切窗口后，"查回复下面"误判有新消息，各多回了一句（只在白名单会话里）。原因没查清，D11 前要查。
- **开着的会话有动图时：** 聊天区一直变，每变一次就查一遍，费时间但不误判。
- **耗时：** 会话已开着时，准备+开会话 1.2 秒；要切换会话时 2–4 秒。模型那几步 11–33 秒。

## 调通过程中修的问题

| 问题 | 原因 | 修法 |
|---|---|---|
| 门铃漏响 | 先扫描后记门铃样子，中间来的消息被算进旧样子 | 先记样子再扫（TIBO） |
| 回复后马上来的消息漏掉 | 电脑上刚发出消息后极短时间内来的新消息不出角标（TIBO 发现） | agent 回过的会话一直盯聊天区，变了就数"我们的回复下面"的深色像素 |
| 停靠「微信支付」 | 切走前那 1 秒多照样漏，停靠的点击还会清掉角标 | 放弃 |
| 编号重复 | N 每次从 1 起，旧气泡里有同一句，模型以为已回 | 回复带启动时分 |
| 回完好友误判 `other` | 标题条把右上角图标认成"?""#+#" | 标题条右边 160 宽不要 |
| 双人时模型点错会话、被放弃后整轮不回 | 列表在重新排序，模型从看到点要好几秒 | 程序按标题找行点开、核对标题；放弃 60 秒后解除 |
| 切换会话漏消息 | 点 B 会清掉 A 的角标，A 开着时来的消息可能不出角标 | 切走前用点之前那张图查 A；查不清的回头再点开查（TIBO 的主意） |
| 点击和打字落到别的窗口 | 微信没拉到前台，程序没检查 | 拉不到前台就不动 |
| 打的字没进输入框 | 程序点列表后焦点在列表上，模型的 type 直接粘贴 | 点开后再点一下输入框 |
| 每条回复慢 4–7 秒 | 会话开着也照走列表 OCR 和点击、核对时多 OCR 聊天区、窗口大小对也等 0.5 秒（Codex 分析） | 开着就只点输入框；只认标题条；大小对就不设 |
