# 托盘换新（做法 2）实施方案 v2

11/21 定。v1 经 Codex 审核后修订，**文末"v2 修订"一节和前文冲突时以 v2 为准**。分支 `codex/tray-v2`（从 `codex/s3-demo` 的 3168fe67 新建），工作树 `D:\Newitem\edge-agent-s3`。

## 背景和已定的事

- 11/20 实测：在同一个开局下（Chrome 提前打开、任务说法改具体），S3（DeepSeek 规划 + Spark UI-TARS 定位）B 站任务 5 步 90 秒；UI-TARS Desktop（只用 Spark UI-TARS-1.5-7B）B 站任务 11 步 83 秒，用户确认成功。UI-TARS 每步约 7 秒，S3 每步 18–24 秒。用户判断深色模式 UI-TARS 也能完成，不再测。
- 用户定：
  - 电脑助手改成 UI-TARS 那一套。
  - 托盘做成一个整体：微信回复、邮件回复、电脑助手都在一个主窗口里，点一下就能启动。
  - 界面美化（配色、字体、图标、动效）不在本方案里，以后由另一个会话做。本方案只搭结构、接功能，样式沿用现有 `STYLE`。
- 日程：
  - 11/21 做电脑助手。
  - 11/22 上午换主窗口；下午回归测试，录备用视频。
  - 11/23 彩排。
- 电脑助手这一块不加安全防护，行为和 UI-TARS Desktop 保持一致（用户 11/19 定："唯一指标是演示效果"）。微信相关的硬规则靠两点保证：
  - 运行前微信由用户手动收进托盘。
  - 运行期间停掉微信自动回复，结束后恢复。

## 目标和完成条件

1. **电脑助手**：托盘里跑 UI-TARS 循环，连 Spark 的 `ui-tars-1.5-7b-awq`。在统一开局下，B 站和深色模式两个任务各连续成功 3 次，每次不超过 3 分钟，全程无人干预。
2. **主窗口**：一个窗口，左边三个入口：微信、邮件、电脑助手；右边是对应的页面。原有功能一项不少，具体见第 4 节"必须原样保留的接口"。
3. **回归**：
   - D16 原有的离线测试全部通过。
   - 真机上，白名单好友发一条微信、测试邮箱收一封信，界面显示正常，按钮都能用。
   - 电脑助手跑完以后，自动回复按原来的参数恢复。

## 1. 电脑助手内核：照抄 UI-TARS Desktop 0.2.4

参考代码：`docs/reference/ui-tars-desktop-0.2.4-摘录.js`，摘自本机已安装的版本，也就是 11/20 实测用的那个。实现以它为准，不以网上 README 为准，两者有出入。

要照抄的行为：

| 项 | UI-TARS Desktop 0.2.4 的做法 |
|---|---|
| 提示词 | `getSystemPromptV1_5(language='zh')`，原文照抄。框格式是 `<\|box_start\|>(x1,y1)<\|box_end\|>`，动作里有 `call_user()` |
| 消息格式 | 第一条用户消息 = 系统提示词（在 `## User Instruction` 之前插入历史）+ 任务原文。之后每轮：截图作为一条 user 消息，模型回复作为一条 assistant 消息（`toVlmModelFormat` / `convertToOpenAIMessages`） |
| 历史图片 | 最多保留最近 5 张（`MAX_IMAGE_LENGTH = 5`），多出来的从最早的删，连同对应的占位一起删（`processVlmParams`） |
| 截图 | 全屏 PNG，按逻辑分辨率（本机是 1920×1080，DPI 100%）；不超过 `MAX_PIXELS_V1_5` 时不缩小 |
| 请求参数 | temperature 0，top_p 0.7，max_tokens 65535（V1_5），单次超时 30 秒，OpenAI 兼容 Chat Completions |
| 坐标换算 | `smartResizeForV15(屏高, 屏宽)` 算出模型看到的尺寸（factor 28）；模型坐标 ÷ 该尺寸 → 0–1 → × 屏幕宽高（`parseActionVlm` + `parseBoxToScreenCoords`）。本机 1920×1080 对应 1932×1092 |
| 执行 | 见 `NutJSOperator.execute`：<br>• click、双击、右击：先移过去，等 100ms 再点<br>• type：Windows 上走剪贴板 + Ctrl+V，用完把剪贴板恢复成原内容；内容以 `\n` 结尾就按回车<br>• hotkey：按 `keyMap` 映射<br>• scroll：先移到点上，滚 500<br>• wait：等 5 秒<br>• drag：拖动 |
| 循环 | 每步执行完等 `loopIntervalInMs`（本机设置是 1000ms）；最多步数用本机设置的 25；遇到 `finished` / `call_user` 结束；解析不出动作时照原版处理 |
| 重试 | 原版 model maxRetries 默认 0。我们加一处：连接错误重试 2 次，每次间隔 3 秒，还不行就以"Spark 连接中断"结束。原因是 11/20 实测断过一次，台上要能看出是网络问题 |

实现位置：新包 `agent/computer/`，替换 `agent/s3/`。

- `uitars.py`：纯函数。负责拼提示词和消息、裁剪历史、解析回复（Thought / Action / 参数）、smart resize 和坐标换算。不碰屏幕，不联网，可以离线测。
- `worker.py`：子进程。截图 → 请求模型 → 解析 → 执行 → 输出 JSON 事件。
  - 沿用 S3 worker 的 Job Object 和停止文件机制。
  - 每步截图存到 `%LOCALAPPDATA%\edge-agent\computer\runs\<时间>\`，不放在项目里。
  - 事件格式沿用 `agent/s3/protocol.py` 的 `EventLines`，字段按 UI-TARS 改：`thought`、`action`、`point`（屏幕坐标）。
  - 解释器暂时用 `config.json` 里 S3 用的 Agent-S venv（里面已有 pyautogui、pyperclip、openai、PIL），不装新包。执行层用 pyautogui 实现上表的行为。worker 不 import D16 的 `agent` 包，避免和托盘进程互相影响。
- `runner.py`、`session.py`：从 `agent/s3/` 搬过来改名。和微信监听的互斥逻辑（等监听真正退出、保存 `last_extra`、只恢复一次、退出托盘时先停电脑助手）原样保留，测试一起搬。
- `config.json`：把 `s3` 段换成 `computer` 段，包括解释器路径、`base_url`、`model`、`api_key`（"EMPTY"）、`max_loop`（25）、`loop_interval_ms`（1000）、`language`（"zh"）。

## v2 修订（综合 Codex 审核意见，以此为准）

摘录已补上循环后半段（`docs/reference/ui-tars-desktop-0.2.4-摘录.js` 最后一段，main.js 99831–99960 行）：逐个执行动作、结束判断、每轮间隔。

### A. 内核行为（补全第 1 节）

1. **消息和历史**：分两类。
   - 跨轮历史：在 `## User Instruction` 之前插入 `## History Messages`，取最后 30 条，用 `human:`/`assistant:` 标注。本项目每次运行都是新任务，所以这一段为空，但拼装函数照原版实现。
   - 本轮会话：只删掉最早的截图和它对应的占位，已经生成的 assistant 文本全部保留。assistant 文本先经过 `getSummary` 去掉 `Reflection:` 段。每张截图单独作为一条 user 消息，内容是 `image_url`。
   - 请求补上 `stream: false`。`thinking` 参数在单步冒烟时试一下 Spark 收不收，不收就去掉。
2. **解析**：按原版 `parseActionVlm` 的兼容范围来。
   - 支持 `Action：`（全角冒号）、缺 `Action:` 前缀、`Reflection` / `Action_Summary` 段、双换行拆出的多个动作。
   - 坐标兼容 `start_box`/`point`/`start_point`/`end_point`，以及 `<point>`、`<bbox>`、`<|box_start|>`；四个值取中心，两个值视为一个点。
   - **偏离原版的一处**：`type(content=...)` 里有引号、逗号、`\n` 时，原版会截断正文（Codex 已复现）。我们改成正确解析，并用带引号、逗号、中文、末尾 `\n` 的用例测试。
3. **循环**：照摘录。
   - 一次回复里的多个动作按顺序执行；解析出的空动作、未知动作记一步但不执行。
   - 遇到 `finished` 或 `call_user` 立即结束。
   - 每轮结束等 1000ms。
   - 上限 25 步，在截图之前检查。
   - 结束结果分 5 种，界面分别显示：`DONE`（模型说完成，请核对）、`CALL_USER`（请求协助）、`STEP_LIMIT`、`ERROR`（附原因：Spark 连接中断 / 超时 / 解析失败 / 执行异常）、`STOPPED`（用户停止）。
4. **坐标**：
   - 截图按 1920×1080 发送；1932×1092 只用来把模型坐标换回 0–1。
   - 执行坐标统一由 `start_box` 换算出来，红圈用同一个实际落点，不另算。
   - 首版只保证单个主屏、100% 缩放，其他情况在界面上提示"未验证"。
5. **执行**（用 pyautogui 复刻 NutJS 的行为）：
   - `type`：剪贴板 + 按住 Ctrl+V 50ms，松开后等 50ms，恢复剪贴板，再按需按回车。粘贴出异常也要在 `finally` 里恢复剪贴板。
   - `hotkey`：读 `key` 或 `hotkey`，按空白或 `+` 分隔，忽略大小写，认不出的键丢掉。
   - 点击：支持 `click`、`left_double`、`right_single`，都是先移过去等 100ms 再点。
   - 拖拽：先移到起点等 100ms，再拖到终点。
   - 滚动：先移到点上，只支持上下两个方向。滚多少用 B 站页面实测校准，和 UI-TARS Desktop 滚一次的距离对齐。
   - `wait`：等 5 秒。
6. **重试只有一层**：只有连接错误重试，最多 2 次，每次隔 3 秒。超时（30 秒）和 HTTP 配置错误不重试，直接以 `ERROR` 结束并写明原因。

### B. 进程和交接（替换第 1 节里 worker、runner、session 的写法）

1. **停止**：worker 每步开始前和执行完动作后，各检查一次停止标志（Runner 写一个停止文件）。看到标志就收尾退出：恢复剪贴板、松开按键。等 5 秒还没退出，再走现有的强杀：`taskkill /T /F` + Qt kill，Job Object 兜底。
2. **结束顺序**：
   - 读到 `done` 事件以后，还要等进程真正退出，才进入收尾。
   - **监听不再自动恢复**。结果页上放一个"完成，恢复自动回复"按钮，用户点了才按原来的参数恢复，且只恢复一次。这样监听启动时把微信切到前台，就不会盖住结果页（Codex 指出的焦点冲突）。
   - 托盘退出时：先结束电脑助手，再走原来的监听退出流程，退出期间不重启监听。
3. **事件约定**：
   - 步数范围 1 到 `max_loop`。
   - 事件字段：`n`、`thought`、`action`（动作名 + 参数的简短说明）、`point`（屏幕坐标，可以没有）、`shot`（截图路径）、`screen`（`[宽, 高]`）。
   - 结果值就是 A.3 列的那 5 种。
   - 运行期间每步上报一次耗时；结束时分开报"等监听退出用了多久"和"任务本身跑了多久"。
4. **配置**：
   - 保留 `config.json` 的 `s3` 段，另外新增 `computer` 段，内容见第 1 节。
   - 新的 Runner 只读 `computer` 段，不碰 DeepSeek 凭据。
   - 像素上限也放在 `computer` 段里，不复用 `grounder_max_pixels`。

### E. 顶部白边（11/21 用户提出，核对后补充）

- **以前的发现**：`experiments/wechat-vision/pad_test.py` 和 `agent/tools/screen.py:35` 记录过一个问题：UI-TARS 对贴着图片顶边的元素，点击会偏下约 28px；在顶部补 56px 白边后，准确率从 33/38 提到 37/38。
- **那次的条件和现在不一样**：
  - 截图是微信窗口的局部，不是全屏。
  - 图片先压到约 100 万像素（`grounder_max_pixels`）再交给模型。
  - 用的是单句定位提示词，不是 agent 提示词。
  - 本方案照 UI-TARS Desktop 发全屏 1920×1080 原图，不压缩。28px 恰好等于模型的一个图块大小，所以偏差很可能和压缩有关，但还没验证。
- **对我们的影响**：全屏截图最上面就是 Chrome 的标签栏和地址栏，正好贴着顶边。如果偏差还在，点地址栏、标签这类操作会受影响。
- **做法**：
  - 默认不补白边，和 UI-TARS Desktop 保持一致。昨天它用全屏原图跑通了 B 站任务。
  - `computer` 配置里加一个 `pad_top` 开关，默认 0。补边以后，坐标的分母按补边后的尺寸重新算，y 再减掉补边的高度。截图回放和红圈仍然用原图坐标。
  - 真机冒烟加一项：在同一张有 Chrome 的全屏截图上，各请求 3 次，目标是顶边的元素（地址栏、当前标签、标签关闭按钮），分别不补边和补 56px，比较落点和目标框的偏差。偏差大于 10px、而且补边能修正，就把默认值改成 56。
