# D9 开工说明（11/6）

D9 的设计和分工。工具层、演示、骨架、学习笔记 03 和练习 5 已在 11/6 写完；剩 TIBO 填 `pick_sessions`、`serve`，然后验收。

## 目标

现在的 agent 要人下命令才动。D9 要让它常驻：有人发消息过来，它自己醒，找出是哪个会话，按顺序一个个回。

通过线（计划书第四节）：测试好友发 20 条，5 秒内全部发现；两人同时发，两人都要回到。

## 定下来的设计

1. **角标负责发现，账本 `pending` 负责记住。** 原来想的是"未读角标就是队列"，11/6 实测推翻了：当前开着的会话来消息会出角标，但在微信里随便点一下它就消失，agent 去回别人时第一下就会点掉它。所以扫到过的都记进 `pending`，回成功才划掉。不开线程，回完一个就重新扫一遍。
2. **总数字一变就醒，变多变少都醒。** 这一条推翻了之前"只在变多时醒"的说法。原因：要分清变多还是变少，得认出红点里的数字，白字红底加上"99+"，OCR 很容易认错。醒一次只扫一遍会话列表，不调大模型，成本很低。扫完没有该回的会话，就接着睡。这样门铃练习里说的"读掉未读也会响"就不是问题了。
3. **一个会话回一次。** 好友连发 5 条，列表里还是一行，只回一句。
4. **第一版回复写死：`测试回复 N`。** N 从 1 开始，每回一条加 1。不读消息内容，也不调模型写回复。
5. **白名单用 `test_contacts.local.json` 的 `allowed_chats`。** 不在里面的会话一律跳过，群不碰。跳过的时候只打印"跳过 1 个非白名单会话"，不打印标题。

## 要小心的坑（TIBO 写 `serve` 时重点想）

- **回失败了，角标也没了。** 靠账本 `pending` 重试，同一个会话最多失败 2 次，超过就放弃，并打印出来。
- **开着的会话来消息（11/6 已测）：** 会出角标，包括刚按完回车的状态；但在微信里随便点一下就消失。剩一个小缝：最后一次扫描到 agent 第一下点击之间，刚回完的那个会话又来消息，会被点掉。验收时留意。
- **每回一个之前都要重新确认窗口：** `check_responsive`，窗口大小 960×800。微信被挡住或者最小化了要停下，不能硬操作。
- **什么时候退出：** 跑满设定的时长，或者 Ctrl+C。退出前打印一共回了几个会话、失败了几个。

`find_unread_rows` 的实现要点：用 `find_red_dots` 只在会话列表那一列找（x 在导航栏右边、`LIST_RIGHT` 左边）；角标在头像右上角，标题用 OCR 读头像右边、同一行上半截那一块。坐标线和 D8 一样，都是按 960×800 量的。

## 验收怎么测

1. **20 条：** 一位测试好友每次发 1 条，等收到回复再发下一条，一共 20 轮。记三个数：发现了几条、回对了几条、有没有误发。
2. **5 秒：** 门铃每次醒的时候打印时间。用手机往文件传输助手发几条，用秒表看从点发送到控制台打印隔了多久。
3. **两人同时发：** 两位好友约好同一分钟各发 1 条，两人都要收到回复，而且不能回错人。
4. **别的会话来消息：** 非白名单的会话来消息时，不能有任何动作。
